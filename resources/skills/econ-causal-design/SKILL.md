# 经管研究设计与因果识别

本工作流基于 AER-Skills 的 identification 与 robustness 技能进行中文适配。来源、固定版本及修改说明见 [SOURCE.md](SOURCE.md)，上游许可见 [LICENSE](LICENSE)。它提供可执行的研究方法工作流，不代表期刊、导师或真实审稿人的意见。

## 工作原则

- 从研究问题、数据结构和分配机制选择方法。描述、预测、测量与理论研究都有价值，不强迫所有问题改成因果研究。
- 明确区分用户事实、已读取的材料、实际计算结果、分析假设和待核验事项。无数据时给条件设计，不能生成一张看似真实的回归表。
- 优先利用会话中的研究背景、文件和已完成结果。仅对影响估计目标、识别、成本或权限的缺口提问；其余工作继续推进。
- 用户要求分析且条件具备时，完成代码、执行、诊断、修正和交付；不能停在问卷、方法名或代码模板。用户要求只读审查时保持只读。
- 不编造文献、政策时点、数据可得性、样本量、系数、显著性或诊断结果。不以调参追求显著，不覆盖原始数据。

## 1. 将问题变成可以检验的设计

先形成一个简短的设计记录；只在有必要时向用户索取缺项：

| 要素       | 必须说明的内容                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------- |
| 研究问题   | 对什么单位、在哪个场景、比较什么变化、回答什么问题                                                 |
| 研究类型   | 描述、预测、测量、因果、理论或结构模型；混合任务分别交付                                           |
| 目标参数   | 例如总体均值、预测误差、ATE、ATT、组别时间效应、阈值附近局部效应或特定人群效应；说明单位与时间范围 |
| 变量与测量 | 结果、处理/暴露、处理时间、机制变量、处理前混杂因素；概念如何映射为字段/量表/文本指标              |
| 数据证据   | 实际文件与字段、来源、覆盖期、样本单位、连接键；已取得、可申请与待核验分开                         |
| 识别依据   | 随机分配、阈值规则、政策差异、工具变量或条件可忽略性等；制度事实与推测分开                         |
| 最主要威胁 | 选择、反向因果、遗漏变量、测量误差、政策叠加、溢出、失访或时间错配                                 |

测量型研究先检查构念定义、编码规则、效度、可靠性、样本外验证与标注一致性。管理学问卷的信效度不能自动解决共同方法偏差或反向因果；文本指标不能只凭几个示例就宣称有效。必要时画时间线或因果图，区分混杂因素、处理后变量、碰撞变量与中介，避免把“加入更多控制变量”当作识别。

理论或结构研究需写清行为假设、均衡/约束、可识别参数、校准或估计所需矩条件及可检验含义，不伪装成准实验。

## 2. 选择与数据支持相符的方法

| 场景                             | 可考虑的方法                       | 需要的证据与解释边界                                                   |
| -------------------------------- | ---------------------------------- | ---------------------------------------------------------------------- |
| 描述或预测                       | 描述统计、回归关联、适当的预测模型 | 明确总体与抽样；预测做时间/实体隔离及样本外评价；好预测不等于因果      |
| 可观测因素足以解释处理选择       | 调整回归、匹配、加权、双重稳健估计 | 讨论条件可忽略性、重叠与模型设定；不可观测混杂仍是风险                 |
| 个体或集群随机分配               | 实验、随机鼓励设计                 | 核查随机化单位、执行偏离、失访、干扰；区分分配效应 ITT 与依从者效应    |
| 处理组与对照组在时间上有不同暴露 | DID 与事件研究                     | 处理规则、可比对照、平行趋势、无预期及干扰边界；确认哪些组别时间有支持 |
| 外生变化推动内生变量             | IV                                 | 相关性、外生性、排除限制；需要时讨论单调性及局部解释                   |
| 预定规则在阈值附近改变处理概率   | Sharp/Fuzzy RDD                    | 分配规则、阈值操纵、连续性、局部样本与第一阶段                         |
| 少数处理单位与较长处理前序列     | 合成控制及扩展                     | 供体可比性、处理前拟合、外推程度、供体污染与干扰                       |
| 暴露份额与共同冲击相乘           | Shift-share/Bartik                 | 明确识别来自份额还是冲击，并采用相应诊断与推断                         |

固定效应、匹配、机器学习和扩大样本量本身都不能保证消除内生性。没有可信因果依据时，保留可识别的关联/描述目标并说明限制；也可提出获取更合适数据的下一步，不能编造一个工具变量补救。

### DID 与事件研究

1. 核对单位、时间、首次处理时点、是否存在退出或重复处理、政策公告与实施的差别。明确结果定义、ATT 等目标及聚合权重。
2. 两组两期 DID/TWFE 在相应识别条件下可估计 ATT；不能因为存在个体异质性就一律禁用。多期错位实施且效应随组别/时间变化时，常规 TWFE 可能混入不适当比较，应解释目标与权重，并考虑组别时间 ATT、插补或交互加权等与设计相容的估计量。
3. 未处理组与尚未处理组是否可作对照取决于该时点的处理状态、无预期、干扰及共同支持。不能一概排除“后来也处理”的单位，也不能让已经处理的单位未经论证承担对照角色。没有对照支持的后期效应不得照常报告。
4. 用处理前图形、系数及区间、适当的联合检验和制度证据诊断趋势。处理前检验不显著不能证明平行趋势；考虑检验功效和合理趋势偏离的敏感性。仅有少数处理前时点时如实说明信息不足。
5. 按处理分配层级、误差相关与抽样结构选择推断。解释聚类数与小样本问题；必要时使用适用的小样本、随机化或自助法推断。Bacon 分解与敏感性界限仅在其模型和数据适用时采用。

### IV 与弱工具变量

1. 说明内生性来源，分别论证相关性、排除限制和外生性；随机化工具不自动意味着排除限制成立。列出可能的直接渠道及可核验的反证。
2. 报告与模型及误差结构相符的第一阶段诊断，如第一阶段系数、部分 R²、适用的 F/有效 F 等。不存在适用于所有模型的 F=10 或 F=50 通过线；不能仅凭一个阈值宣称工具强或置信区间可靠。
3. 如弱识别值得担忧，采用与维度、异方差/聚类设定相容的弱工具稳健推断，例如适用的 Anderson–Rubin 或条件似然比方法，并解释区间可能不有界或不连通。LIML 的点估计不能自动替代有效推断。
4. 过度识别检验仅在适用设定下使用；不拒绝不能证明全部工具有效。单一恰好识别模型不能靠过度识别检验验证排除限制。
5. 根据模型说明估计对象；二元工具/处理且满足相应假设时讨论 LATE 与依从者，连续工具或不同设定不能机械沿用同一解释。OLS 和 IV 可能针对不同参数，差异本身不是“稳健”或“失败”。

### RDD、合成控制与 Shift-share

- RDD：说明局部估计对象、阈值规则及 sharp/fuzzy 类型；关注有效样本、离散运行变量和阈值附近可操纵性。通常从有依据的局部低阶估计、带宽选择及适用的偏差校正推断开始，避免高阶全局多项式。密度、处理前协变量连续性、带宽/核敏感性、伪阈值或 donut 分析按威胁选择；不把单一密度检验不显著当作无操纵的证明，donut 也不能自动修复识别。
- 合成控制：检查处理前拟合、供体污染、权重集中与预处理窗口。没有适用于所有项目的“至少10期”门槛；可用时间长度与识别能力需结合过程讨论。时间/空间 placebo、留一供体分析及扩展估计量按需求选用；置换尾部比例只有在相应分配或可交换性条件下才有其推断解释，不自动称为精确 p 值。
- Shift-share：明确外生份额或外生冲击路径。前者关注份额及驱动权重，后者关注冲击层面的有效独立变化与推断；不能用一个普通聚类回归替代对识别来源的论证。

### 实验与观察性管理研究

- 实验先记录随机化单位、分层/集群、主要结果、分析窗口、依从性、失访与潜在溢出。依据设计估计 ITT，必要时讨论其他参数；基线不显著不是随机化有效的证明，已知随机化设计也不应被单个不平衡 p 值推翻。
- 根据任务阶段评估样本量、设计效应与可检测效应；将预先计划和事后探索分开。已完成实验不能补写成“事前注册”；注册、伦理或目标期刊要求应核对具体适用规定，不编造通用强制门槛。
- 观察性研究必须声明可忽略性/重叠等条件。匹配或加权后检查协变量平衡、极端权重及目标人群变化；面板固定效应只消除其模型能吸收的异质性，不能消除任意时变混杂。

## 3. 稳健性围绕威胁组织

先列“威胁—为什么可能发生—检测/敏感性方案—所需数据—会改变什么结论”，再执行有判别力的分析。不是每个项目都要做表内每一项。

| 威胁                 | 可选分析                                      | 必须避免                                                  |
| -------------------- | --------------------------------------------- | --------------------------------------------------------- |
| 测量或口径错误       | 核验单位、分母、平减、定义和替代有效指标      | 任意 log/level 变换、缩尾至显著；变换改变参数却不解释     |
| 样本选择或失访       | 样本流程、组间失访、适用的加权/界限/敏感性    | 机械删成平衡面板，或把选择修正模型视为无条件解决方案      |
| 少数单位或时期支配   | 数据错误核验、影响诊断、预先说明的留一分析    | 仅因观测削弱结论就删去；无理由删除最高1%                  |
| 混杂或模型设定       | 理论合理的调整集、函数形式、未观测混杂敏感性  | 加入处理后变量，或把换成 IV 当作例行稳健性                |
| 相关误差与小样本     | 与抽样/分配相符的聚类、适用的小样本推断       | 按显著性挑聚类层级，机械报告三个聚类方案                  |
| 反事实趋势或叠加政策 | 事件研究、替代窗口/可比对照、合理趋势偏离分析 | 只展示最好看的窗口，或把预趋势不显著当证明                |
| 替代解释             | 有依据的负向对照、伪时间/伪结果及制度核验     | 忽略 placebo 的识别假设和功效，把零结果当排除所有替代机制 |
| 多重分析与异质性     | 明确假设族、合理的多重检验处理、预设/探索标签 | 只报告显著子组或选择性展示规格                            |

记录每次合理规格的动机、样本、变量定义、估计对象、系数、区间与运行结果。规格曲线仅用于事先说明的合理选择集合，不能混入无效规格凑数量。跨规格参数、单位或样本变化时先解释可比性。

异质性优先使用有理论依据的分组或交互，并对组间差异作直接检验及区间报告。一个组显著、另一个组不显著，不意味着组间效应显著不同。探索性切分如实标注，考虑多重比较和精度。

机制证据区分“符合某渠道的辅助结果”和“识别中介因果效应”。控制中介后的主效应变化、子组差异或几个方向一致的系数都不能独自证明机制。说明中介识别所需附加假设、处理后混杂和替代解释；证据不足则降低结论强度。

## 4. 在 EconoMind 中执行并保留证据

1. 读取会话里实际可用的文件、工具清单和当前环境信息，优先复用已有成功结果。确认真实列名、单位/时间键、样本范围、缺失和重复、处理编码与量纲。没有数据时交付条件方案及具体数据需求，禁止用模拟值填补结果；用户另行要求模拟时明确标注。
2. 数据与授权齐备后，用实际暴露的 `notebook_execute` 执行 Python/R，按其当前 schema 提供语言和代码。先核查输入与小规模计算，再拟合选定模型、执行必要诊断。调用成功不等于统计有效；读取实际输出并核对估计对象、样本和推断。
3. 版本兼容确有需要时用 `inspect_packages`。明确缺包时通过 `manage_packages` 在正确的会话绑定环境安装必要依赖，检查返回的 `ok`、`target`、`packageChanges` 和 `needsRestart`；需要重启时调用 `notebook_restart`，再运行导入与受影响单元。不得在 Notebook 内用 `%pip`、`!pip`、`install.packages` 或子进程绕过包管理。安装成功也须以真实导入和计算结果确认可用。
4. 默认使用现有语言和运行时，不为本任务随意更换用户环境。用户指定远程计算时先发现真实主机和已配置运行能力，不能虚构 provider 或本地替代远程执行；缺少必要主机环境时说明限制并保留可执行代码。
5. 使用可追溯的项目相对路径保存脚本、结果表、图和必要说明；保留原始数据及既有用户结果。记录模型公式、样本过滤、估计量、标准误、依赖版本、随机种子（若涉及随机过程）与运行标识。完成的计算不因交付步骤失败而无理由重跑。
6. 输出文件确实由成功运行生成后，使用 `write_artifact_file` 导出。传入 `filename`、`source: { kind: 'localPath', path: ... }` 和该生产运行实际返回的 `producerRunId`。本地 Notebook 文件的 `filename` 与 `source.path` 使用同一个真实相对路径；绝不臆造 runId、路径或发布成功状态。分别报告计算完成和导出成功，失败时保留已生成的文件并修复交付。

导出调用的字段关系示意（变量均来自真实运行；不是可直接粘贴的固定值）：

```javascript
write_artifact_file({
  filename: relativePath,
  source: { kind: 'localPath', path: relativePath },
  producerRunId: runId
})
```

若某工具、语言或估计量不可用，先核实限制；可选择满足同一统计目标的已验证实现并说明差异。确实无法执行则明确交付代码/计划及尚未运行的步骤，不能把换一种不等价的回归当作成功替代。

## 5. 交付与停止条件

按任务大小交付一份能直接支持下一步的说明，而非固定长度报告：

- 研究问题、目标参数、数据证据与变量操作化。
- 主设计、关键假设、实际估计量及其适用性；为何比其他候选更合适。
- 已执行结果：效应大小、单位、区间、样本与推断方式；未执行部分单独标注。
- 最关键的识别威胁、对应诊断/敏感性证据，以及剩余限制。
- 若做异质性或机制，说明直接检验、探索属性及解释边界。
- 已保存或成功导出的代码、结果与复现入口；仅链接真实文件。

不显著结果应结合区间和实质相关效应解释；不把“未拒绝零效应”改写成“没有影响”，也不凭宽跨零区间宣称方向确定。没有强因果证据时限制为关联结论。完成与请求相符的分析及相关核验后停止；不为通过一套固定清单补做与问题无关的检查，更不能承诺录用或伪造人的认可。
