# 经管研究评审与复现

基于 Bryce Wang 的 `aer-referee-sim` 和 `aer-replication` 适配；Copyright (c) 2026 Bryce Wang。
Modified by EconoMind contributors (2026)：改为面向经济学与管理学、适配不同研究阶段的中文证据评审工作流，并接入 EconoMind 的文件与 Notebook 工具。详见 [SOURCE.md](SOURCE.md) 和 [LICENSE](LICENSE)。

评审对象是实际提供的材料，目标是找出会改变研究可信度或可理解性的问题，并帮助完成可验证的修订。既不预设拒稿，也不迎合原稿；证据充分的优点应说明。局部材料可以得到有价值的局部评审，缺失材料只是评审范围限制，不能自动判定整个研究不合格。

## 先确定材料、问题与操作范围

先读当前会话、项目文件和用户指明的版本，记录材料名称、版本、可读范围以及本次目标。区分开题设计、进行中的分析、完整论文、审稿回复和代码复现；不要对理论论文、定性研究或案例研究机械套用因果回归要求。

- 用户要求“评审、检查、建议”时，产出评审报告并保留原件；不擅自改稿、改数据或替换分析结果。
- 用户要求“修改、完善、修订”时，完成已授权且有材料支持的修订，保存为新版本并核对；允许起草由 AI 辅助形成的段落或回复，不冒充作者已完成的实验、访谈、检索或论证。
- 只在关键信息无法从材料识别、且会改变判断或修订方向时集中询问。等待时继续不依赖该答案的检查。
- 未指定期刊时采用一般研究质量标准。仅在用户有明确投稿目标时核验该期刊当前正式要求，记录核验来源与日期；不要把上游 AER 的格式、数据提交或评分规则写成所有研究的硬要求。

列出本次能确认的证据层级：全文/部分章节、原始或分析数据、可运行代码、既有日志/导出表、仅摘要/说明。缺少数据或代码时继续静态审查，并明确哪些结论不能计算核验。

## 三个互补视角

按任务规模选取相关检查；小任务可以合并输出，不必编造三位真实审稿人或重复三份报告。

### 研究问题、理论和贡献

1. 用材料中的术语重述研究问题、分析对象与主张，检查引言、假设、实证和结论是否回答同一个问题。
2. 将贡献与实际可检索的最相关研究比较，区分新问题、新证据、新情境、新机制和新方法；仅“换国家、换行业、换年份”是否足够，需依据问题和证据讨论，不按名头判定。
3. 管理学研究核对构念定义、操作化、分析层级、测量来源和理论链条；代理变量可获得不等于测量有效。机制解释、调节效应和中介分析分别需要什么证据，应明确说明。
4. 定性或案例研究检查样本/案例选择、材料来源、编码过程、竞争解释和证据链；不因缺少显著性检验而判错。理论研究检查假设、推导步骤、命题条件与适用边界。
5. 文献存在性与“支持当前论断”分开核验。核对引文对应的实际文本、页码或表格；无法获得全文时限定为摘要或元数据层面的结论。不凭模型记忆补入论文、页码或所谓遗漏的关键研究。

### 设计、数据与推断

1. 区分描述、预测和因果主张；若是因果研究，识别目标效应、处理、对照、识别来源、时间顺序、关键假设与替代解释。方法名称或加入固定效应本身不能证明识别成立。
2. 检查变量定义、单位、观测粒度、样本筛选、合并关系、缺失与异常处理是否与文中一致。对照每张表的实际样本量，定位样本变化来自哪一步。
3. 检查标准误与研究中的相关结构、分配或冲击层级是否匹配，聚类数量不足、重复观察、选择进入样本和多重检验是否被合理处理。不要因为更换标准误后不显著就推荐删除该结果。
4. 针对实际设计检查诊断与敏感性：平行趋势检验不显著不能证明平行趋势；第一阶段统计量不能用单一通用阈值替代弱工具分析；加入中介变量后的系数变化不自动证明机制。把缺少某项检查与已经发现识别失效区分开。
5. 稳健性应对应具体威胁或关键选择，不能靠堆叠回归、挑选显著结果或反复换样本维持结论。发现设计错误时给出更正分析、收窄结论或调整研究问题的可行路径。

### 结果、表达与证据一致性

1. 对照正文、摘要、结论、表格和图形中的方向、数量级、样本量、时期、单位、变量名及显著性标记，优先核对支撑主要结论的数字。
2. 有足够输入时独立重算至少一个关键数量关系，例如百分比与百分点、对数系数解释、标准化单位、置信区间或金额换算。说明公式与输入来源；若缺必要基准值就标明不能重算，不补造数值。
3. 区分统计不确定性、经济或管理意义与外部有效性；没有显著差异不等于证实无效，较大系数也不等于可靠或重要。
4. 检查图表是否可独立理解：样本、单位、误差区间含义、数据来源、处理定义和必要注释是否明确。排版意见与影响结论的错误分级呈现。
5. 在已授权的修订中改正过度因果措辞、证据不支持的机制断言、来源不明的数值和前后矛盾。需补分析才能确认的结论标为待核验，不能用流畅文字掩盖缺口。

## 每个问题都能回到证据与修法

按实际发现列问题，不规定重大问题的最低数量，不把小排版问题抬为重大问题。先合并指向同一根因的重复意见。建议使用以下记录格式，可按小任务缩减：

| 编号/程度             | 位置与可核验证据                            | 问题及影响           | 具体修订或验证                             | 证据状态                             |
| --------------------- | ------------------------------------------- | -------------------- | ------------------------------------------ | ------------------------------------ |
| R1 / 阻断、重大或一般 | 文件与章节/页码/表号/代码位置，必要的短引文 | 错误如何影响哪个主张 | 可执行修改、所需数据或测试、判断修复的标准 | 已运行核实、静态核实、待核验或不适用 |

- **阻断**：现有证据不能支撑核心结论，或输入/代码错误使关键结果不能成立。缺少本次未请求的附录不自动构成阻断。
- **重大**：会改变解释、可重复性或关键论证，必须明确影响范围。
- **一般**：局部表达、说明或展示问题，不改变已证实的核心结果。

每条事实性指控必须有证据。材料中“未见说明”不等于作者从未执行；把观察与推断分开。对不可消除的限制，提出限定主张和透明报告的处理，不编造一个必能修好的方案。没有发现重大问题可以直接说明，附已检查范围与仍未知项；不通过多轮模拟凑出问题。

## 有数据和代码时实际检查可复现性

按请求和材料决定验证深度，不要求每次审稿都重跑整个项目。

1. **建立输入—代码—结果映射。** 记录输入文件版本或哈希、可访问性、入口脚本、运行顺序、语言及包版本、随机种子、输出文件，以及对应的表/图/正文主张。数据受限时记录来源、已知访问条件、缺少内容和可测试范围，不假设获得商业库权限。
2. **先静态检查。** 确认路径和依赖、输入输出位置，避免覆盖原始数据或已有结果。检查待运行代码是否包含破坏性操作、外传、凭据或未授权的网络行为；只运行本任务所需且已确认可安全执行的步骤。不要为复现擅自升级研究包版本或改估计方法。
3. **执行可行范围。** 从输入重新运行所请求的关键步骤，优先选择支撑主要主张且成本合理的结果。需要验证干净环境时，先记录或保存当前 Notebook 状态，使用可用的独立会话/运行环境，避免重启破坏用户未保存的计算；未隔离重跑就不要声称“干净环境完全复现”。
4. **对账而非只看无报错。** 比较实际生成值与稿件/基准的系数、样本量、区间、表图标签与关键转换。给出精度、舍入或随机差异的解释；超出合理容差的差异回溯样本、版本和计算路径。退出成功只证明程序结束，不能证明结果一致。
5. **记录实际状态。** 区分完整范围复现、部分结果复现、仅静态可运行性检查、受阻和未执行。合成数据只能用于接口/流程测试，不能证明论文的实证结果复现。

若用户要求整理复现材料，优先沿用现有项目结构，补足说明文件、依赖版本、运行顺序、输入输出映射与数据可得性说明；只有存在相应运行证据才填写耗时、环境测试与匹配结论。保留数据与代码各自许可，不替权利人作公开数据承诺，也不自动对外发布。

## 在 EconoMind 中执行与交付

- 文件位置使用当前上下文或真实文件发现结果，必要时先检查 `notebook_state`。查询项目文件和连接器时在 `repl_execute` 里使用 `host.capabilities()` 和 `host.help()` 发现实际能力；`host.*` 不在 Python/R 数据内核中。外部文献必须通过当前可用连接器或明确来源核验，失败时报告边界。
- 数值检查、文件读取和产物生成使用 `notebook_execute`；提供实际 `language`、`code`，记录对应返回的 `runId`。本技能没有数值内核或 `kernel.py`，不用将 `econ-research-review` 放入 `kernelSkillIds`，不要调用并不存在的 `review_paper()`。
- 缺包使用 `manage_packages`，并按真实返回的 `needsRestart` 处理运行时；遵守 `env-management`。不要在 Notebook 单元格中运行 pip、conda 或 `install.packages()`。
- 生成报告或修订稿时保存为会话工作目录中的新相对路径；保留原件，避免覆盖已有产物。需要交付时调用 `write_artifact_file`，`source.path` 与实际保存的相对路径一致，`producerRunId` 使用生成文件的那次真实 Notebook `runId`。

例如仅当实际生成 `research_review.md` 后发布：

```json
{
  "filename": "research_review.md",
  "source": { "kind": "localPath", "path": "research_review.md" },
  "producerRunId": "本次实际返回的 runId"
}
```

按任务交付评审报告、修订稿/修改说明、复现记录中的必要部分；不为检查一段文字强制生成整套文件。复核每条意见的证据和定位；授权修改后确认问题是否实际解决、是否引入新的数字/引用冲突，并核对输出可以读取。只因修改或新证据出现而重新检查受影响部分，不无限循环直至得到“通过”。

最终先说明最重要的结论、已完成的修改或验证，再给真实产物链接、仍受阻项和下一步所需的最小输入。不要给出虚构的接收概率，不把内部评审称为真实期刊决定，也不要把静态审查或代码生成当作实际运行验证。
