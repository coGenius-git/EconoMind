# 经管数据审计与清洗

基于 Ninh Nguyen 的 `data-auditor` 适配；Copyright (c) 2025 Ninh Nguyen。
Modified by EconoMind contributors (2026)：增加中文数据审计、可复现清洗和 EconoMind 工具执行流程。来源与修改记录见 [SOURCE.md](SOURCE.md)，原始许可见 [LICENSE](LICENSE)。

把“数据源听说有这个指标”与“已取得能回答该问题的数据”分开。有数据就实际检查和计算；需要清洗就执行已授权的处理并留下记录。没有数据时核验可得性，交付证据明确的数据需求表和下一步，不能编造样本量、质量结论或检查通过记录。

## 使用现有材料开始工作

先利用当前会话、项目文件、已有变量说明和研究设计识别研究对象、观测单位、时期、频率、Y、X 及已明确的控制变量。用户要求数据整理、清洗、描述统计或可视化，即授权完成相应必要工作；不要把任务退回为一串访谈问题。低影响的可逆细节采用合理默认并说明。

只在关键信息无法从材料确定、且会改变含义或样本时集中询问，例如：同一企业年度多条记录究竟表示业务分部还是重复观测、金额是元还是万元。等待时继续其他独立审计。用户仅要求审查时只报告问题，不生成擅自改变口径的清洗结果。

## 在 EconoMind 中执行

- 从当前提供的文件信息或可用文件工具取得真实路径；路径不明时检查 `notebook_state` 的会话目录与状态，不猜测 Windows 路径。保留原始文件；在会话工作目录使用新的相对文件名保存产物，不覆盖已有路径或在技能目录写结果。
- Python/R 计算使用 `notebook_execute` 的实际 `language` 和 `code`；复用已有数据和单元格 `cellId`，保留成功返回的 `runId`。本技能没有 `kernel.py` 或注册函数，不需把 `econ-data-audit` 放入 `kernelSkillIds`，也没有可直接调用的 `audit_data()`。
- 外部数据连接器在 `repl_execute` 中按 `host.capabilities()`、`host.help()` 的真实能力使用。数据内核不能调用连接器；较大数据通过 `OPEN_SCIENCE_HANDOFF_DIR` 交接。缺少数据权限时说明具体阻碍，不假定拥有 CSMAR、Wind、Orbis 等账户。
- 缺包按 `env-management` 使用 `manage_packages`，收到 `needsRestart` 后先 `notebook_restart`。不要在 Notebook 或 Shell 内运行 pip、conda、`install.packages()` 或第三方安装脚本。
- 保存最终文件后使用 `write_artifact_file` 发布为项目产物，`source.kind` 为 `localPath`，`source.path` 与刚保存的相对路径一致，`producerRunId` 来自生成该文件的真实 Notebook 运行。以返回的链接交付；写入失败不能称为交付成功。

例如，只有实际已生成 `data_audit.md` 且保存了该次 `runId` 时，才调用：

```json
{
  "filename": "data_audit.md",
  "source": { "kind": "localPath", "path": "data_audit.md" },
  "producerRunId": "本次实际返回的 runId"
}
```

## 数据尚未取得：核验可得性

建立“变量—构念—测量—来源—单位/层级—时间/频率—可访问状态—证据”映射。对计划来源核对实际页面、数据字典、样例或用户已持有文件；记录准确来源和核验日期。

- 状态区分：已取得并检查、已确认可获取但尚未取得、需申请/付费、仅候选来源、现有来源无法提供。公开的介绍页面不能证明某个字段或时期可下载。
- 检查是否真的存在所需 Y/X、处理开始时点、单位标识和必要覆盖；X 不一定是政策或二元处理，描述性研究不强行改造成因果研究。
- 控制变量先核对因果角色与测量时点，不能按“所有能取得的列”自动纳入；标记可能的处理后变量、中介、碰撞变量和未来变量，将取舍理由交给研究设计判断。行政数据、问卷和代理指标都需具体核验误差与覆盖，不能只凭数据类型断言质量更好。
- 核对数据层级能否对齐；重复截面不能假设同一受访者跨期跟踪。非平衡面板可以有效，不能仅为“平衡”而删样本。
- 给出对当前问题的结论：可继续、附条件继续、关键输入受阻。每个受阻项写明缺少什么、证据及可行替代；“未找到”不等于不存在。不要替用户购买数据、申请账户或上传原始数据。

## 已有数据：先审计，再处理

按实际任务选取适用检查，并用 Notebook 执行。记录输入文件版本或哈希、文件/工作表、读取参数、编码、行列数、字段类型、观测粒度、时间范围与真实观测数；不能用 N×T 代替非平衡数据的实测行数。大文件可分块或抽样探索，但将抽样范围和未完成的全量检查标清。

### 主键与合并

1. 找到能标识一条观测的候选键，检查键缺失、键重复和完全重复行；区分冲突记录、多证券/多报表口径、分部或交易明细，不自动 `drop_duplicates()`。
2. 企业代码、证券代码、行政区划码保留字符串和前导零；检查名称变更、跨库编码、行政区划调整、财政年度/自然年度、公布日/报告期。只有来源有依据的映射才用于转换。
3. 合并前声明期望 `1:1`、`m:1` 或 `1:m` 关系；分别检查左右键唯一性和缺失键。避免缺失键互相匹配。用 `merge(validate=..., indicator=True)` 或语言对应约束执行，并记录匹配、仅左、仅右的数量及重复键分布。
4. 合并后检查行数与唯一单位数变化，解释一对多展开。无意的多对多笛卡尔扩张属于阻断问题，先定位，不通过随意去重掩盖。需要桥接表、聚合或多对多关系时说明观测单位和规则，并保留原记录对应关系。

### 缺失、异常与统计口径

- 报告变量缺失数及比例，分时期、组别、关键处理状态检查模式；区分结构性缺失、未适用、未披露、真实零值和特殊编码。替换特殊编码必须有字典证据，不能把所有 0 当缺失，也不能以“随机缺失”概括未经检验的机制。
- 检查合理取值、极端分位数、不可能日期、跨期跳变及会计关系；异常只是待核查信号，先区分录入错误、经济事件、比例分母接近零和正常尾部。保留原值及异常标记。
- 金额核对币种、元/千元/万元、名义/实际价格、基年及汇率日期/平均口径；百分数核对 0—1 或 0—100，收益率核对简单/对数口径。不得把缺少通胀指数的名义值称为实际值。
- 频率转换区分存量、流量和比率：不能对所有列统一求和/均值；解释年末存量、期间流量和加权汇总的选择。核对滞后、滚动窗口、发布时间和信息可得日期，避免把未来信息带入当期。
- 描述统计给出实际有效样本量、均值/标准差、中位数/分位数、最小最大值及缺失情况，按变量类型选择统计；相关矩阵注明样本删除规则，面板数据说明混合、单位间或单位内比较的含义。图表从同一份已验证数据生成并标注单位、时期和样本。

### 执行清洗并保留样本变化

在用户授权范围内，按已确定规则在副本执行类型转换、编码统一、数据合并、变量构建、筛选和描述统计，交付实际结果与可复现代码。原始列或原文件要能恢复处理前的值。

每一步记录规则、理由、受影响行数、变动前后观测数/单位数，以及被排除观测的可追溯标识和原因。分组/分期比较样本流失；合并未匹配、缺失删除、行业筛选和模型样本删除不能混在一个“最终样本”数字中。分析脚本从不可变输入重新运行应得到一致结果，不依赖手工编辑中间表。

Winsorization、截尾、插补、删极值、强制平衡面板均不是默认操作。任务或既有研究方案已明确规则时执行并报告阈值、组别、受影响数量，保留处理前变量；未明确且会改变研究结论时先输出诊断与备选处理，不擅自选能提高显著性的规则。插补不等于观测到真实值，缺失导致的选择偏差不能仅靠均值填补消除。

## 交付与完成标准

按任务规模复用项目现有命名与结构；不为小任务强制创建一整套文件。常见完整产物为：

- `data_audit.md`：关键发现、证据、影响范围、已完成处理、仍受阻项、是否足以支持下一步分析。
- 数据字典及样本流转表：定义/公式、来源、单位、时间口径、缺失规则、处理规则和逐步样本量；可合并进一份工作簿。
- 请求清洗时交付新数据文件、可运行的清洗代码或 Notebook，以及必要的合并/异常/排除记录。仅审计时保留原数据，只交审计产物。

发布前重新读取输出，确认字段、类型、行数、主键与关键统计和报告一致；核对原始数据未被改写、合并基数未意外改变、样本流转数字可以对账。根据任务说明统计发现的经济含义，清楚区分事实、解释和因果假设。不声称运行过未执行的检查，不用演示数据代替用户数据制造“通过”。

回复先说最重要的数据结论和已交付结果，再给产物链接及影响使用的限制。若输入不可得，交付已核验的可行性表和最小所需输入；若工具或权限受阻，说明已完成部分和具体失败，不退回空泛建议。
